# Little Wishes 2.0 ♡

Личный вишлист на русском языке: адаптивный интерфейс, коллекции, автоматический импорт публичных метаданных товара, мультивалютность, приоритеты, бюджет и история покупок.

## Новое в 2.0

Soft Editorial: контрастная пастельная палитра, редакционная типографика, новые иллюстрации демонстрационных товаров, адаптивные карточки и формы, улучшенный фокус и доступность. Все данные и функции v1 сохранены; ключ локального хранилища не изменён. См. DESIGN.md и AGENTS.md.

## Быстрый запуск на Netlify — полный режим (рекомендуется)

Для серверного импорта товаров нужна Netlify Function. Никаких API-ключей для базового импорта и курса валют не требуется.

### Через GitHub

1. Распакуйте `little-wishes-v2-source.zip`.
2. Создайте **новый** репозиторий `little-wishes` на https://github.com/new (лучше Private, без README при создании). Загрузите содержимое распакованной папки, включая `netlify/`, `public/`, `netlify.toml`.
3. В Netlify: Add new project → Import an existing project → GitHub → выберите новый репозиторий. Разрешите Netlify доступ к нему, если потребуется.
4. Build command — пусто; Publish directory — `public`; Functions directory — `netlify/functions`. `netlify.toml` уже содержит настройки.
5. Нажмите Deploy. Откройте выданный HTTPS-адрес. Проверьте импорт, добавив ссылку на публичный товар со Schema.org Product или Open Graph.

Команды для загрузки через Git (в папке с `netlify.toml`, после создания пустого репозитория):

```bash
git init -b main
git add .
git commit -m "Initial Little Wishes release"
git remote add origin https://github.com/YOUR_USERNAME/little-wishes.git
git push -u origin main
```

### Через Netlify CLI — без GitHub

Потребуется Node.js 22+ и npm, интернет и вход в Netlify. В корне распакованных исходников:

```bash
npx netlify-cli login
npx netlify-cli init
npm run deploy
```

Если `init` предлагает непрерывный деплой, можно вместо него выполнить `npx netlify-cli sites:create` для создания проекта и привязать каталог `npx netlify-cli link`. Затем выполнить `npm run deploy`. Для локальной проверки с серверной функцией: `npm run dev`.

### Через Netlify Drop — только статическая версия

Распакуйте `little-wishes-v2-netlify-drop.zip`, затем перетащите папку с `index.html` в https://app.netlify.com/drop. Статическая версия работает без сборки и без функций. **Автоимпорт по ссылке в ней ограничен страницами, разрешающими CORS; большинство магазинов не разрешают.** Ручное добавление, фотографии, курсы валют, коллекции, статистика, экспорт и снимки списков работают. Для полноценного импорта используйте GitHub или CLI выше. Не загружайте исходный ZIP как статический корень: `index.html` находится в `public/`.

## Страницы

- Обзор — общая стоимость, количество желаний, исполненные желания, быстрый импорт, коллекции и карточки.
- Все желания — поиск по названию, описанию и заметкам; сортировка по цене, желанности, срочности, дате; фильтры и группы; сетка/список.
- Коллекции — пользовательские подборки, цвет, стоимость, добавление и редактирование. Удаление коллекции не удаляет её товары.
- Избранное — отбор понравившихся желаний.
- Исполнено — история покупок с возможностью вернуть товар в активный список.
- Статистика — расходы по категориям, бюджет, распределение желаний по силе.
- Настройки — имя, валюта, бюджет, обновление курсов, резервная копия, поделиться снимком списка.
- Карточка товара — описание, URL, изображение, цена, количество, доставка, целевая цена, размер/цвет, дата, заметки, статус, сердечки 1–5 и срочность 1–5.

На мобильном «Избранное» и «Статистика» находятся в разделе «Ещё».

## Как работает автоматизация

`POST /.netlify/functions/import-product` принимает `{ "url": "https://…" }` и извлекает Schema.org Product / Offer, Open Graph и другие HTML-метаданные. Категория определяется по метаданным, названию и описанию на русском/английском; если не удалось, используется «Другое». Для фото поддерживается URL либо загрузка PNG/JPEG/WebP/GIF с уменьшением до 850 px (GIF сохраняется как статичный кадр). Ссылка проверяется, форма заполняется, пользователь подтверждает данные и сохраняет карточку. Повторный импорт запускается в редакторе и позволяет проверить обновлённые сведения до сохранения.

Магазины с CAPTCHA, антиботом, авторизацией или полностью динамическим рендерингом могут не отдавать нужные данные; автоматизация не обходит защиты магазинов. Неизвестная цена не подменяется нулём, неявная валюта не угадывается. При агрегированных предложениях может использоваться минимальная цена; проверяйте конкретный вариант товара. Для магазинов с отдельными официальными API в будущем можно добавить адаптеры. В статическом режиме предусмотрен ограниченный браузерный CORS-импорт.

Курс: `https://open.er-api.com/v6/latest/USD` (ExchangeRate-API, открытый доступ; ориентировочное обновление раз в сутки, не банковские котировки). Полученные курсы кешируются; приложение обновляет их при открытии при отсутствии/устаревании кеша и по кнопке. Исходная цена и валюта товара не меняются. Формула пересчёта из A в B: `value / rate[A] * rate[B]`. Итог = цена за штуку × количество + доставка за весь заказ в валюте товара. Неизвестные цены или курсы исключаются из суммы и помечаются. Бюджет в основной валюте, купленные товары исключены из активной стоимости.

## Хранение и приватность

По умолчанию **localStorage**, без учётной записи, сервера хранения и синхронизации устройств. Каждое устройство/браузер имеет независимые данные. Резервные копии JSON включают загруженные фото и личные заметки; импорт заменяет текущие данные после подтверждения. При большом количестве загруженных изображений возможен лимит браузера; сделайте резервную копию. Смена домена, очистка данных или приватный режим могут сделать данные недоступными.

Поделиться — снимок текущего списка в URL-фрагменте, не живой список. Снимок не содержит личных заметок и фото, загруженных с устройства; ссылки на товары, описание и удалённые фотографии остаются. Получатель может сохранить копию, которая дальше независима. Длинные списки передаются через JSON. Никто не должен передавать ссылку, если не хочет делиться данными. Удалённые картинки загружаются браузером с сайтов магазинов; они могут быть недоступны или измениться. Сайт не запрашивает платёжные данные.

Для общего синхронизируемого вишлиста с авторизацией рекомендуется отдельный следующий этап: Supabase Auth + Postgres с RLS (owner_id, share tokens, роль viewer/editor), Storage для фотографий, политика доступа к изображениям, миграция локальных данных и обработка конфликтов. Не реализован в этой версии.

## Архитектура

```
public/
  index.html       — HTML оболочка
  style.css        — адаптивная дизайн-система
  app.js           — маршрутизация по hash, UI, модель данных, валюты, экспорт
  icon.svg         — favicon
  _headers         — CSP и защитные заголовки для статического деплоя
netlify/functions/
  import-product.cjs — получение HTML, парсинг, проверка публичных адресов
netlify.toml       — конфигурация деплоя
package.json       — команды запуска, теста и деплоя
tests/             — тесты парсера
```

Vanilla JavaScript + CSS, без runtime-зависимостей, сборки или отдельного VPS. Серверная функция ограничивает время, размер HTML и перенаправления; блокирует внутренние IPv4 и IPv6, проверяет DNS и закрепляет публичный IPv4 для соединения. Серверная функция не является публичным прокси сырого HTML. Для открытого массового сервиса нужна дополнительная авторизация/rate limiting, журналирование и мониторинг лимитов Netlify. Не полагайтесь на эту реализацию как на завершённый security audit.

## Проверки

```bash
npm test
node --check public/app.js
```

Тесты проверяют Schema.org, Open Graph, цену/валюту, агрегированные предложения, относительные фото и недопустимые адреса. Основные сценарии UI дополнительно проверены в Chromium с имитацией FX API, функции импорта и хранилища. Живые сетевые запросы к магазинам/Netlify не проверены в среде генерации. Демонстрационные товары и цены вымышлены; в снимках интерфейса используется тестовый курс.
